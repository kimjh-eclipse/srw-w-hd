# 섬광 꼬리93813·93814 재교정 후보

## 원인 정정

- 이전 전체 섬광 재제작에서 흰 중심을 강조하면서 실제 꼬리의 금색/노랑을 흰 선으로 잘못 그렸습니다.
- 93813의 실제 불투명20픽셀은 금색12·노랑7·흰색1이며, 93814의20픽셀은 금색11·노랑6·흰색3입니다. 이 색 비율과 실제6개 분리 성분을 원본 제작 입력으로 삼았습니다.
- 무지적93815의 흰 중심 영역은 다시 그리지 않았습니다. 라이브의 기존 자체 HD 그림을 그대로 복사해 원래 영역을 보존했고 `normal_93815_preserved.json`에서 RGBA SHA256 일치를 확인했습니다. 원본 RGB/알파를 후보에 찍은 것이 아닙니다.

## 최종 입력

- 같은 ID2개만: `install_contract.json`의93813/93814입니다. 정상58개와 추가 무지적4개는 설치 입력에 넣지 않았습니다. 신규 연결과 새 고유 대상 수는 늘리지 않습니다.
- `native_atlas.png`(48×24), `candidate_atlas.png`(정확한4배192×96), 생성 원천 `generated_selected.png`, 성분/위치 근거 `source_components.json`·`provenance.json`입니다.
- 후보의 원래 사각형은93813 [0,16,32,8], 93814 [32,0,16,16]이고 정상93815 [0,0,32,16]은 보존됩니다. 각기 실제 원본 `spec.source_x/source_y`는 기존 계약에 유지했습니다.
- 실제6개 성분을 생성 도구로 각각 새로 그려 같은 성분 상자와 위치에 조립했습니다. 금색으로 채운 면을 흰 윤곽으로 대신하지 않았습니다. 원본 알파/RGB 전사나 강한 알파 문턱은 사용하지 않았습니다. 생성 자체 알파를 유지하고 경계 상자 탐색에만8을 사용했습니다.
- `source_input_check.json`에서 최종 두 사각형의 실제 인덱스·16색과 원본 불투명 RGB/알파가 동일합니다. 동일 최종 좌표로 NullCache 준비2개가 모두 비지 않으며 기존 ID 해시·인덱스와 같습니다.
