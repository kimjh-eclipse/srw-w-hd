# 슈퍼로봇대전 W 초상화 HD 자료

원본 ROM의 56×48 초상화 IMG와 바로 뒤의 16색 PLT를 대조해 548개 원본을 추출했습니다. 인물·로봇 얼굴·동물·통신 장치와 표정/색상/복장 변형을 포함합니다. 548명의 서로 다른 인물이라는 뜻은 아닙니다. 별도 IMG33836은 흑백 통신 잡음이어서 초상화 수에 넣지 않았습니다.

실제 게임에서 확인한 12개는 개별 AI 그림을 사용하고, 나머지 536개는 16개씩 배치한 34개 시트를 AI로 다시 그렸습니다. 모든 생성에는 내장 image_gen 도구를 사용했습니다. generation_prompts.json, generation_extra_prompts.json 및 sheets/generation_* 파일에 프롬프트와 생성 출처를 기록했습니다.

library.json이 실행 시 읽는 목록입니다. 얼굴 내부의 원본 5비트 색상을 정확하게 확인한 뒤, 원본의 불투명한 얼굴 전체를 다시 대조해 표정과 복장이 잘못 연결되는 것을 막습니다. 전투·상태·시나리오의 타일 단위 세로 위치를 확인합니다. 원본 투명도와 HUD 보호 마스크를 적용해 프레임과 대사 글자를 보존합니다. 최대 32개의 HD 얼굴 그림만 메모리에 유지합니다.

검사 결과: test_current/portrait/catalog_verification.json에 원본 548개와 3개 위치(총 1644건)의 연결 검사 결과를 저장했습니다. test_current/portrait/verification.json에는 실제로 관측한 12개 얼굴의 교체와 HUD 보호 검사가 있습니다. status_hd.png는 실제 상태 화면의 카즈마 얼굴 교체 결과이며, in_game_comparison.png는 관측한 12개 얼굴의 비교입니다.

전체 카탈로그의 연결 검사는 원본 이미지로 구성한 화면을 이용한 검사입니다. 실제 게임 전 구간에서 모든 표정이 등장하는 장면을 재생한 검사는 아닙니다. 화면에 페이드·섬광 등 색상 효과가 적용되어 원본 색상과 일치하지 않을 때는 게임의 원본 표시를 유지합니다.

ROM을 수정하지 않고 전용 에뮬레이터가 HD 그림을 표시하는 방식입니다. 기존 승인된 기체 얼굴과 파츠 목록은 변경하지 않았습니다.

## 초상화 성능 개선

처음 보는 얼굴도 게임 프레임 안에서 PNG 해독·축소·마스크 합성을 하지 않습니다. 최종 얼굴은 별도 준비 스레드에서 읽고, 준비되기 전에는 원본을 계속 표시합니다. 스레드 우선순위와 대기열(최대 16개)을 제한했고 객체가 해제되면 스레드도 자동으로 정리되므로 호출부에 close를 추가할 필요가 없습니다.

native_reference.npz는 548개 작은 원본 검증 자료를 프로세스당 한 번만 읽는 약 0.55MiB 압축 파일입니다. prepared.sqlite는 최종 315×270 얼굴 텍스처 548개를 미리 압축한 약 89MiB 디스크 캐시입니다. 이 파일 전체를 메모리에 올리지 않고 필요한 얼굴만 풉니다. 캐시가 없거나 원본 파일의 수정 시각·크기가 달라지면 기존 PNG를 별도 스레드에서 준비하는 방식으로 돌아갑니다. 그림을 다시 생성한 경우 scripts/assets/build_portrait_reference_cache.py와 scripts/assets/build_portrait_texture_cache.py로 캐시를 갱신할 수 있습니다.

두 화면을 함께 측정한 결과 첫 얼굴의 프레임 내 처리 평균은 26.0ms에서 0.75ms, 준비된 얼굴은 0.76ms였습니다. 첫 프로세스 준비는 약 92ms, 같은 프로세스의 두 번째 렌더러는 약 2ms였습니다. 40개 얼굴을 교체한 뒤 두 렌더러의 추가 작업 메모리는 약 32MiB였으며 각 HD 캐시는 32개로 제한됐습니다. 준비된 얼굴 및 얼굴 없는 반복 프레임에서 파일 읽기는 없었고, 새 얼굴에서도 게임 프레임 스레드의 그림 파일 읽기는 없었습니다. 수치는 측정 당시 환경 기준이며 운영체제 파일 캐시를 강제로 비우지는 않았습니다.

실제 에뮬레이션 240프레임 검사에서도 얼굴 준비 도중 게임은 계속 진행됐습니다. 준비 작업 없는 프레임 평균 11.9ms, 준비 작업을 겹친 프레임 평균 11.4ms로 이 검사에서 지속적인 추가 지연은 관측되지 않았습니다. 이는 전체 캠페인 검증이나 모든 시스템에서의 속도 보장을 뜻하지 않습니다. 측정은 test_current/portrait/performance_two_screens.json, async_verification.json에 기록했습니다.

## 같은 화면의 복수 초상화

실제 플레이에서 한 NDS 화면 위쪽 브레스와 아래쪽 카토르가 함께 나올 때 아래 얼굴만 교체되는 문제가 확인됐습니다. 첫 번째 일치에서 그리기를 끝내던 처리와 단일 얼굴 캐시가 원인이었습니다. 이제 화면 안의 모든 겹치지 않는 얼굴을 확인해서 각각 그립니다. 찾은 얼굴뿐 아니라 검색 영역 전체의 원본 변경을 확인하므로 아랫얼굴은 그대로이고 윗얼굴만 바뀌거나 새로 나타나도 갱신됩니다. y0/y24처럼 겹치는 위치는 하나의 얼굴 영역으로 처리합니다.

548개 원본을 상하 짝으로 구성한 548개 화면에서 총 1096개 얼굴을 확인했습니다. 브레스+카토르 동시 표시와 윗얼굴만 듀오로 교체하는 경우, 윗얼굴 삭제·복귀도 검사했습니다. 두 NDS 화면에 총 네 얼굴을 표시한 처리 시간은 평균 1.32ms(p95 1.41ms), 첫 처리 1.72ms였고 반복 이미지 파일 읽기는 없었습니다. 앞의 0.75ms 측정은 두 화면에 얼굴 하나씩, 총 두 얼굴 조건이므로 네 얼굴 조건에 그대로 적용할 수 없습니다.

이는 원본 자산을 같은 화면에 배치한 연결·합성 검사입니다. 실제 사용자의 진행 상태 재생 확인 및 전체 캠페인 검증과 구별해야 합니다. 자세한 결과는 test_current/portrait/multiple_faces_verification.json에 있습니다.
