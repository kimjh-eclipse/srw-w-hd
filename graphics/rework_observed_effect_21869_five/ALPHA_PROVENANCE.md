# 생성 알파 처리 기록과 한계

- 필터 전 원본은 generated_0.png, generated_1.png 등으로 그대로 보존했습니다. 생성 파일 출처는 generated_files.json입니다. 원본은 candidate.png의 이진화 알파와 다릅니다.
- 이번 제작의 정확한 기준: 각 생성 그림의 자체 알파가 220 이상이면255, 미만이면0으로 바꾼 뒤 MinFilter(3), MaxFilter(3)를 순서대로 적용했습니다. 이후 자체 알파 bbox를 원본 bbox 위치에 맞춰 배치/리사이즈했습니다. 원본 알파를 생성 그림에 복사하지 않았습니다.
- 이 기준은 부드러운 실제 광채와 가는 선·작은 분리성분을 지울 수 있습니다. 생산 maxA/빈 그림 검사는 시각 품질이나 발광 보존의 증거가 아닙니다. 분리성분 제거 수는 production_report.json에 있습니다.
- Claude는 필터 전 generated 이미지와 최종 candidate/실제 장면을 비교해 손실을 판정해야 합니다. 자동으로 모든 FX에 적용할 권장 공통 규칙이 아닙니다. 보존 알파 후보를 선택할 경우 메인이 재연결·재굽기해야 합니다.
- 이번에 이미 인계한 후보는 바꾸지 않았고, 라이브/DB/runtime 수정도 없습니다. 이후 제작 helper의 기본은 생성 알파 보존입니다. 이 묶음의 재현용 manifest에는 이전 기준을 명시했습니다.
