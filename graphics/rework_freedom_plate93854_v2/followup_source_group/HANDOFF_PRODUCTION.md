# 최근 재검사6개 후속 후보

기존 후보를 설치한 뒤 같은 도구로 재검사해 남은6개에 대한 후속 그림입니다. 이전 경고가 사라졌다는 새 독립 판정은 하지 않았습니다. 아래 후보6개만 교체하고 정상58개는 변경하지 않습니다. 신규 연결과 새 고유 그림 수는 늘리지 않습니다.

| 대상 | 설치 입력 | 교정 원인 |
|---|---|---|
|93681/93687|`slash_pair/install_contract.json`|큰 묶음 경계만 맞추면서 성분 위치가 어긋났습니다. 실제9+9개 연결 성분을 각각 새로 그려 원래 성분 상자와 위치에 조립했습니다.|
|93813/93814/93815|`burst_three/install_contract.json`|한 실제44×24 섬광의 갈래와 흰 중심/노란 경계 비율이 달랐습니다. 전체 섬광을 다시 그린 동일 원천을 원래3사각형에 나눴습니다.|
|93854|`freedom_one/install_contract.json`|원본 본체와 떨어진 아래3×1 조각 때문에 전체 경계로 맞추면 본체가 늘어났습니다. 본체32×12와 아래3×1을 별도 생성 자체 알파로 배치했고, 밝은 은색 면을 줄여 짙은 청회색 면을 다시 그렸습니다.|

- 각 폴더에 원본 `native_atlas.png`, 정확한4배 `candidate_atlas.png`, 최종 설치 `install_contract.json`, 원본/후보 `source_candidate_pair.png`, NullCache `production_input_check.json`이 있습니다.
- `source_input_check.json`에서 최종 설치 원본 좌표의 불투명 RGB·알파가 실제 계약 인덱스·16색과 동일함을 확인했습니다. 최종 설치 좌표로 NullCache 준비6개 모두 비지 않으며 기존 ID의 실제 해시·인덱스와 같습니다.
- 그림은 생성 도구로 다시 만들었습니다. 원본 알파/RGB 전사나 강한 알파 문턱으로 모양 검사를 맞추지 않았습니다. 생성 알파는 그대로 두고 경계 상자 탐색에만8을 사용했습니다. 성분 위치/크기만 원본 계약 기하에 맞췄습니다.
- `generated_slashes.png`, `generated_burst.png`, `generated_freedom.png`가 생성 원천입니다. 원본 성분 목록/각 생성 영역은 하위 `provenance.json`과 상위 자료에 보존했습니다.
- 새로운 전체 검사·실제 재생 검증은 수행하지 않았고 클로드 판정 대기입니다. 상태·프레임·원본 사각형은 각 설치 계약에 기존 실제 관측 계약을 보존했습니다.
- 남은 위험: 작은 대각 성분의 계단/끝 두께, 섬광의 갈래 사이 틈과 약한 노란 경계, 프리덤 검정 면/부품 단절 여부 및 작은 아래 조각의 색. 메모리 준비 통과를 시각 정상으로 표시하지 않습니다.
- 공유 코드·라이브 메타·DB·EXE·배포·푸시는 건드리지 않았습니다.
