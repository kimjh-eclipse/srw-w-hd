대상: `C:/Emul/Workshop/SRW_W_HD/test_current/parts/pose_packets/unit_<번호>/robot_set/`

## 볼 파일
- `SHEET_REVIEW.png` — 왼쪽 = 원본(게임 도트, 4배), 오른쪽 = 코덱스가 그린 HD. 같은 배치.
- `DRAWINGS_STATUS.json` — 자세별 자동 검사 결과. `state: rejected` 인 자세는 `reasons`·`weak`(스프라이트 번호, 칠한 비율, 색 차)를 봅니다.
- 걸린 자세는 `pose_NN/review_fit.png` 도 봅니다 — 왼쪽 원본 4배 | 가운데 정합 보정한 그림 | 오른쪽 차이(빨강 = 원본에 있는데 안 칠함, 파랑 = 원본 밖에 칠함).

## 판정 기준 (원본과 비교)
1. 자세·부품 위치: 팔다리·무장·날개가 원본과 같은 자리·방향·크기인가. 자세가 통째로 빠지거나 칸이 비어 있지 않은가.
2. 부품 내용: 원본에 있는 부품·무장·장식이 다 있는가. 원본에 없는 것을 지어내지 않았는가.
3. 색: 원본 색 계열과 밝기를 지키는가(전체적으로 확연히 밝거나·어둡거나·채도가 높으면 지적). 음영이 원본보다 진한 정도는 괜찮음.
4. 연출: 원본의 연기·사격광·속도선·잔상·빔이 그 자리에 있는가.
5. 화풍 통일: 같은 부품이 자세마다 같은 모양·같은 색인가.
6. 결함: 반투명 회색 판·테두리, 글자, 잘린 부분, 심하게 흐린 해상도.
- 자동 검사의 색 차(`weak` 의 세 번째 값 70~130)는 HD 음영 차이로 오는 경우가 많습니다. 그림을 보고 부품이 제자리에 있으면 문제 아님으로 판정하세요.

## 결과 (반드시 이 파일로 저장)

```
{"unit": 23, "verdict": "ok" | "minor" | "redraw",
 "accept_poses": ["pose_00", ...],          // 설치해도 되는 자세(자동 검사에 걸렸어도 눈으로 문제없으면 포함)
 "reject_poses": {"pose_05": "이유"},        // 설치하면 안 되는 자세와 이유
 "issues": [{"where": "pose_03 / 시트 2행 1열", "what": "무엇이 원본과 다른지 구체적으로", "fix": "코덱스가 고칠 방법"}],
 "notes": "한두 문장 요약"}
```
- `ok`: 그대로 설치. `minor`: 설치하되 다음 판에 반영할 지적. `redraw`: 기체 전체를 다시 그려야 함(자세 대부분이 틀림·색이 전반적으로 틀림·해상도가 너무 낮음).
- 이 파일 외에는 아무것도 쓰거나 고치지 마세요(라이브러리·handoff·그림 파일 수정 금지).
