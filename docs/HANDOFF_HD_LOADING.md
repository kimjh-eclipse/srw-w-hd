# HD 리소스 로딩 개선 인계

## 적용 내용

- 기존 `parts_baked.sqlite`는 가공한 파츠 이미지를, `atlas_digests.json`은 아틀라스 파일의 해시를 보관한다. 새 `parts_catalog.py`는 코어·렌더러·텍스처 작업자가 공통으로 읽는 파츠 목록의 반복 팔레트를 묶어서 저장한다. 원본 JSON의 SHA-256을 확인하며 교체되거나 로컬 캐시가 손상되면 다시 만든다.
- 렌더러가 SQLite에 등록된 파츠를 조회할 때 같은 아틀라스와 등록 방식에서 공통으로 쓰는 문자열을 한 번만 직렬화한다. 파츠 좌표와 기존 키 형식을 유지하므로 기존 설치의 가공 텍스처를 재사용한다.
- 첫 HD 프레임에서 실제 출력 폭에 필요한 UI 글자를 미리 만든다. 이후 해상도에서 필요한 글자는 기존 글꼴 렌더러가 그린다. 코어는 ROM을 처음 읽은 바이트로 해시를 계산해 대용량 메모리 복사 두 번을 줄인다.

## 확인한 결과

- Windows 개발판의 1차 측정에서 코어와 렌더러 준비 시간 중앙값은 10.9초에서 5.5초로 줄었다. 이 값은 캐시를 재사용할 때의 결과다.
- 2차 측정은 같은 시험 ROM과 `emulator/demo.state`로 별도 프로세스를 여섯 번 띄워 1차 개선판과 추가 개선판을 세 번씩 비교했다. 코어 생성 시작부터 960픽셀 첫 전투 화면 합성까지 중앙값이 5.79초에서 4.82초로 줄었다(약 17%). 이 측정은 파일 선택기, 창 표시, GPU 출력 시간을 제외한다. 실행 중 팩이 갱신되어 1차 개선판 세 번째 실행은 9.77초였다.
- 각 비교 쌍의 준비된 바인딩 수가 일치했다. 출력 폭을 960 → 768 → 832 → 960으로 바꾸며 네 프레임을 비교했고 각각 픽셀 해시가 일치했다. 전체 바인딩의 현재 텍스처 키와 표본의 구형 키를 합쳐 114,210건이 기존 계산과 일치했다.
- 파츠 목록의 최초 생성, 동시 생성, 파일 시각과 크기가 같은 원본 교체, 캐시 손상, 캐시 쓰기 실패 시 원본 읽기를 확인했다.

## 클로드 검증 항목

1. 배포 EXE를 다시 빌드해 캐시가 없는 첫 부팅과 재실행을 각각 측정한다. ROM 선택 후 첫 화면까지와 첫 전투 진입 시간을 따로 기록한다.
2. 기존 텍스처 DB가 설치된 상태에서 대기·공격 자세, 컷인, HP/EN 및 대사 글자를 확인한다. 전투 중 자동 해상도가 바뀌는 시점의 프레임 시간도 확인한다.
3. Android 호스트 통합 후 같은 팩으로 첫 가져오기와 재실행, 첫 전투를 실기기에서 측정한다. 이번 수치는 Windows 소스 실행 결과다.

원격 소스 브랜치는 `perf/hd-resource-startup`이다.
